# Data plane

[`BeaRustProxy`](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/proxy.rs) implements Pingora’s `ProxyHttp` hooks. A request takes one loaded runtime snapshot and follows this implemented order:

1. **IP security:** derive the client IP using [trusted-proxy rules](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/security_policy.rs) and block with `403` before routing ([test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/control_plane_security.rs)).
2. **Bot evaluation:** inspect the bounded request fingerprint, honor a valid clearance for challenges, then mark block/challenge outcomes ([module](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/bot_protection.rs), [test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/proxy_bot.rs)).
3. **WAF headers and body:** evaluate headers first, then buffer and inspect no more than `MAX_INSPECTION_BODY_BYTES` through `request_body_filter`; a blocking verdict returns `403` and stops upstream body processing ([engine](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/waf.rs), [store](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/waf_store.rs), [tests](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/proxy_waf.rs)). Optional detector plugins can only escalate a verdict.
4. **Route resolution:** serve HTTP-01 challenges when applicable, otherwise resolve host/path against the [snapshot router](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/router.rs); no route produces `404` ([test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/routing.rs)).
5. **Per-host authentication:** evaluate the host-auth [store](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/security_policy.rs) after a route has been chosen ([test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/control_plane_security.rs)).
6. **Rate limiting:** select a global or host [policy](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/rate_limit.rs) and record/limit the client key ([store](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/rate_limit_store.rs), [test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/proxy_rate_limit.rs)).
7. **Peer selection:** choose a healthy pool backend, optionally through a `balance.select` plugin; no available pool/backend is `503` ([balancer](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/balancer.rs), [tests](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/load_balancing.rs)).
8. **Request transform:** call an optional [transform plugin](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/plugin_runtime.rs) before upstream forwarding. BeaRust then reasserts `Host`, `X-Forwarded-For`, and `X-Request-Id`, so a plugin cannot spoof or remove them ([test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/plugin_runtime.rs)).
9. **Upstream and response transform:** Pingora sends the upstream request; a response-transform plugin uses bounded buffering and chunk framing when needed ([hook](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/proxy.rs), [test](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/proxy_http.rs)).
10. **Logging, analytics, and failures:** completion records redacted [request logging](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/observability.rs) and aggregate [analytics](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/src/analytics.rs) exactly once. `fail_to_connect` may select a different backend according to the failure path; `fail_to_proxy` writes a mapped error when no response exists and records the completion ([tests](https://github.com/rizalord/bearust/blob/c8ed147cd84efc71bda8b8473486906b5616a505/tests/proxy_analytics.rs)).

The ordering matters: header/body security happens before forwarding, host auth/rate limits only after routing, and protected headers are restored after a request transform. Request-time policy snapshots are refreshed by the runtime synchronization path described in [Runtime architecture](./runtime-architecture).
