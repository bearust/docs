# BeaRust documentation

BeaRust is a configuration-driven reverse proxy and load balancer. It puts a Rust data plane in front of application backends and pairs it with an Axum control plane and bundled management UI for operating proxy configuration.

Start with [What is BeaRust?](./introduction/what-is-bearust), then follow the [production installation](./getting-started/installation) and [first proxy](./getting-started/first-proxy) guides. For a high-level view of the components, see [Architecture](./introduction/architecture); for what is optional, disabled by default, or still maturing, see [Feature status](./introduction/feature-status).

## Choose a path

- **Deploy BeaRust:** [Install with Docker Compose](./getting-started/installation), then complete [first-time setup](./getting-started/first-time-setup).
- **Route traffic:** Configure a [first proxy](./getting-started/first-proxy) from the checked-in TOML example.
- **Develop locally:** Start the [development stack](./getting-started/development-stack) with the Rust backend and Vite frontend.
- **Operate production traffic:** Manage [proxy hosts and load balancing](./operate/proxy-hosts-and-load-balancing), then add [TLS and certificates](./operate/tls-and-certificates) and security controls one at a time.
- **Recover from a common issue:** Use [troubleshooting](./getting-started/troubleshooting) for diagnostics and expected observations.

All public guidance is English-first. Keep credentials, private keys, and production URLs out of documentation examples and support requests.
